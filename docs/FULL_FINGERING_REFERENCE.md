# 用户图片的完整陶笛指法参考

本页逐项转录本项目用户提供的 **“Ocarina of Time Remake - Ocarina guide”** 图片，覆盖 **B4–F6的19个半音、26种按法**。图片署名：Guide by Tiny Violet；button icons by Zacksly。

这是对用户图片的转录，尚未在游戏中实测。原版v1.1代码只实现当前示例需要的10个音；下表不能被当作已经扩展了固件功能。完整的机器可读数据见 [oot_user_image_reference.json](../profiles/oot_user_image_reference.json)，当前固件**没有加载这个JSON**。

## 符号

- `L`、`R`是肩键；`A`、`X`、`Y`按Nintendo手柄字母命名。
- `S↑/S↓`是**左摇杆偏转**，不是按下摇杆；`D↑/D↓`是**十字键**。
- 同一按法的`+`表示各输入同时保持；`或`表示两套任选一套，不能把两套合并。
- 不需要的按钮要释放，未使用的摇杆要回中。即使两音按同一个发音键，分开的音也要重新触发。

## 转为当前工程的ControlState

`src/pro_controller.h`中的`right/shared/left`不是GP2040-CE宏的`buttonMask`。它们是本工程原生Pro控制器报告的三个按钮字节，不能直接套用GP2040宏掩码。

| 输入 | ControlState字段 | 位值（十六进制） |
|---|---|---|
| A | right | 0x08 |
| X | right | 0x02 |
| Y | right | 0x01 |
| R | right | 0x40 |
| L | left | 0x40 |
| D↑ | left | 0x02 |
| D↓ | left | 0x01 |

同一字段中的位做按位或。`shared=0`；所有未使用按钮为0。左右摇杆X/Y默认都是2048。左摇杆上设`ly=3748`，下设`ly=348`，回中设`ly=2048`，其他坐标不变。这里Y向上较大是当前Switch Pro原始坐标/校准约定，不能直接套用Windows屏幕的Y方向。

每一套按法的**完整ControlState数值**都已在JSON中列出。例子：

| 音与按法 | right | left | ly | 其余 |
|---|---|---|---|---|
| B4：L+S↓+D↓ | 0 | 65（0x41） | 348 | shared=0，lx/rx/ry=2048 |
| D♯5按法1：L+D↑ | 0 | 66（0x42） | 2048 | 同上 |
| D♯5按法2：R+S↓ | 64（0x40） | 0 | 348 | 同上 |
| F6：X+S↑+D↑ | 2（0x02） | 2（0x02） | 3748 | 同上 |

`pro_controller.cpp`会把`right/shared/left`分别放入完整报告的第3/4/5号字节（从0计数；第0字节是报告ID），左摇杆放入第6–8号字节。`shared`在输出时会额外带上协议的charging-grip位；不要把这个协议位误当成按键。

12位摇杆打包方式：

```cpp
out[6] = lx & 0xff;
out[7] = ((lx >> 8) & 0x0f) | ((ly & 0x0f) << 4);
out[8] = (ly >> 4) & 0xff;
```

## 给后续配置化实现

先将这个参考profile转换成受校验的指法表，或补全`fingering()`，再允许导入器接受其余9个音。JSON里`v1_1_variant_index`从0计数：C6为1，即图中第二套；其他已实现音均为0。`implemented_in_v1_1=false`不是按法错误，而是代码目前没有这个分支。

当前`fingering()`遇到缺失音会返回中立状态。通用导入必须显式检查缺指法并报错；不能仅检查B4–F6范围就宣称都可演奏，也不能通过静默折八度绕过缺失。

待实机验证的范围包括所有19个音、26套组合、修饰同时生效和音符间切换；将来有测试结果时，应逐套记录，不能从一个按法成功推定其替代按法也已通过。
