# 旧版 v1.1：刷写、操作与实机检查

本文保留旧版内置歌曲固件的操作与验收资料。新测试版支持上传换歌，请先看 [使用说明](../开始使用.md)。

## 板子与恢复

只针对普通Raspberry Pi Pico（RP2040，非W）构建。USB线必须支持数据传输。刷写会替换当前运行的GP2040-CE或其他固件；先备份原GP2040-CE网页配置，并保留对应官方Pico UF2。

1. 按住板上BOOTSEL，插入Windows电脑。
2. 出现 `RPI-RP2` 磁盘后松开。
3. 拖入一个UF2，等待自动重启。完整版和短版二选一，不能靠同时拖入实现切换。
4. 恢复原固件时重复这个过程，拖入对应官方Pico UF2，再按需要恢复配置。

专用固件不主动保存配置到Flash；不要据此保证以后任何刷写或新配置功能都能保留原GP2040-CE配置。

## 接主机与演奏

连接Switch 2底座USB口，在系统中启用Pro手柄有线通信（若有该选项）。用原手柄进入游戏陶笛自由演奏界面。Pico的LED常亮表示本程序完成了USB Pro协议初始化状态转换，**不等于游戏输入已实测成功**。

| 操作 | 当前行为 |
|---|---|
| 待机短按并松开BOOTSEL | 倒数3秒，然后播放所编译版本一次 |
| 倒数/播放中再按 | 停止并恢复中立输入 |
| 待机长按约1秒 | 发送L+R约半秒，用于控制器分配；不启动歌曲 |
| GP22接GND | 可选的等效触发方式，无需连接也能用BOOTSEL |
| 拔掉USB | 播放停止 |

BOOTSEL在“插电前按住”与“正常运行后按下”用途不同：前者进入ROM刷机模式，后者由程序读取作为播放按钮。

LED：慢闪=尚未初始化/未连接；常亮=待机；快闪=倒数；中速闪=播放。需要分配控制器时，在系统“控制器→更改握法/顺序”中使用长按L+R，并确认Pico被分配给游戏使用的玩家。游戏声音由主机生成，Pico不是USB音源。

## 首次实测顺序

1. 先确认系统能识别有线Pro控制器及正确的玩家槽位。
2. 确认L+R加入操作和停止操作均可见，不要直接把不响应当成歌曲错误。
3. 在游戏中确认单音和修饰：`L`=D5、`R`=F5、`A`=A5、`X`=D6；左摇杆上/下与十字键上/下必须独立。
4. 最高F6需要同时发送X、左摇杆上、十字键上。若游戏实测不匹配，记录实际音高后调整指法表，不能任意改源旋律八度。
5. 核对第一遍尾句约在试听00:30.5：F5 D5 D5 C5 D5；后续高八度变体是原曲内容。
6. 检查同音重触发、较长间奏后的恢复、结束后中立状态及中途停止。

以上是待执行的硬件验收步骤，当前仓库没有对应的实机通过记录。

## 已知边界

- USB协议实现参考GP2040-CE，但不是完整GP2040-CE驱动功能集合；未实现NFC、真实IMU和完整手柄功能。
- 报告发送目标周期8ms，歌曲按绝对微秒时间调度；实际USB轮询/游戏帧采样会引入时间量化。
- BOOTSEL读取短暂禁用中断并释放Flash CS，使用RAM中的例程；当前只使用一个核心，没有播放期间Flash写入。
- 输入报告队列固定8条，溢出时会丢弃新回复，目前缺少可见诊断；配置化开发应补充观察和错误处理。
- 目前无法把新版歌曲直接传入设备；需要选择预编译UF2或构建源码。
