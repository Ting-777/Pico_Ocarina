# 配置化开发设计（尚未实现）

## 用户要达到的结果

在Windows上导入自己的MIDI，选择主旋律轨、片段、移调、速度和游戏指法，先试听，再上传到Pico。Pico接到Switch后，短按BOOTSEL即可完整演奏；换曲和调参数不必重新编译，也不需要多根GPIO依次触发。

当前v1.1只是固定示例的单核USB HID播放器。`full/first`是构建选择；下面的JSON、配置协议、持久存储和界面都是设计建议，不是已有API。

## 建议分层

1. 电脑端MIDI导入器：解析轨道、tempo map、复音和片段，产生可追溯的单音时间线。
2. 指法配置：MIDI音高映射到独立的按钮位、左右摇杆坐标、十字键；验证全部音符都有可用指法。
3. 公共编译器：同一份时间线同时输出试听MIDI、CSV检查表和设备事件数据，避免试听与固件不一致。
4. 设备配置/歌曲槽：从已验证的存储读取事件，继续用绝对时间调度；保留停止和中立状态。
5. Windows界面：导入、预览、显示错误、上传、回读版本/摘要，并展示设备状态。

建议先提取`Song`、`PlaybackOptions`、`FingeringProfile`接口，保留现有`full/first`作为固定回归样例，再逐步替换编译期数组。

完整指法起点已在[完整指法参考](FULL_FINGERING_REFERENCE.md)和`profiles/oot_user_image_reference.json`中转录：19个音、26套按法，带原生Pro ControlState与v1.1实现状态。它是参考profile，不是已加载的运行时配置；可优先实现校验和转换，再替换10音硬编码表。

## 电脑端配置草案

```json
{
  "schema_version": 1,
  "source": {
    "file": "song.mid",
    "track_index": 2,
    "range": {"start_tick": 4224, "end_tick": 47232},
    "polyphony": "highest"
  },
  "arrangement": {
    "transpose_semitones": 5,
    "tempo_scale": 1.0,
    "octave_policy": "reject"
  },
  "playback": {
    "countdown_ms": 3000,
    "release_gap_ms": 40,
    "repeat_count": 1
  },
  "fingering_profile": "oot-user-reference-v1"
}
```

源路径仅供电脑端使用，不是设备固件的可访问文件路径。音高和音域之外还要验证指法覆盖；当前硬编码表只有10个音。示例中的`reject`表示不允许自动折八度，`highest`表示遇到同时起音取高声部。持续重叠而非同时起音的多声部，需要明确的单音化规则和报告，不能仅按最早/最晚事件截断后假装无损。

速度图、速度缩放与最短松键间隔可能冲突。若最短音间隔小于可演奏的按住+释放时间，必须报出具体小节/音符并要求调整速度或时长；不要静默丢音。

## 设备上传方式：先做兼容性验证，再定接口

当前只有主机有线Pro HID接口。直接加CDC/MSC组成复合设备，可能影响Switch的手柄识别，尚未验证；不要在未测试的情况下把它作为既定方案。

推荐先做一个**独立配置模式**原型：接Windows时进入配置模式、上传并保存，重启/重新枚举回到原来的Pro HID演奏模式。最终进入方式待确定；目前BOOTSEL短按用于播放、长按1秒用于L+R，插电时按住BOOTSEL会进RP2040 ROM，不能直接占用而不设计迁移。

电脑侧可以先用小型Python CLI通过有边界检查的命令上传；确认流程可靠后再做GUI。不需要一开始就引入网页、大型前端或SD卡。

## 存储与协议要求

- 保留固件区域，明确划定歌曲/配置Flash分区，不允许上传覆盖程序或任意地址写入。
- 事件数量、总时长、包大小、坐标和按钮范围有上限；长度与CRC/摘要先验证后提交。
- 配置有schema版本、有效标志和回退默认值；采用双槽/原子提交，模拟断电可恢复。
- Flash写入在停止播放且USB/BOOTSEL访问已协调的阶段执行；不能在QSPI取指或采样临界段中随意写Flash。
- 单核结构先保持，除非明确处理另一核心访问Flash的问题。
- 对外区分“接收”“验证”“保存”“激活”，并能回读当前歌曲摘要、参数与错误码。
- 没有合法配置时保持中立和明确LED状态，不在上电后未经触发自动演奏。

| 阶段 | 交付 | 验收 |
|---|---|---|
| 0 | 真机基线记录 | 识别、玩家分配、10个指法、停止、整曲播放分别记录结果；不能只记LED亮 |
| 1 | 通用电脑端导入器与指法JSON | 当前样例产生相同时间线；支持tempo map；第一遍低尾句、高音变体不变；缺指法明确报错 |
| 2 | 通用播放器接口 | 参数传入而非写死；native tests覆盖倒数、缩放、释放、停止、长休止、越界与异常数据 |
| 3 | 配置模式与上传CLI | Windows上传/读回摘要成功；回演奏模式后真机仍识别；坏包拒绝 |
| 4 | 持久歌曲与配置 | 掉电、坏CRC、版本不兼容、空间不足都能回退；换曲无需重新编译 |
